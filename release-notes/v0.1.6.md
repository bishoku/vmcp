# REST operation and schema workspaces

vMCP v0.1.6 makes large REST definitions easier to edit and explains schema and OpenAPI import failures before they become difficult-to-diagnose tool errors.

## Highlights

- Open REST operations in a modal with separate request/tool, parameter, schema, and advanced settings sections. Apply operation changes to the upstream draft, then save the upstream to publish them.
- Edit request and response schemas in a larger workspace with Example JSON, Fields, and Schema JSON views. Search field names, paths, and descriptions; expand branches individually or together. Field controls are mounted only for expanded branches.
- Choose Merge to retain existing schema rules or explicitly confirm Replace to build a fresh schema from an example. Later examples can fill unconstrained types originally inferred from null values or empty arrays.
- Check schema validity and example compatibility before applying changes. Show mismatches with JSON paths, support visual nullability edits, and check individual schemas and combined MCP input/output shapes against the backend's 64 KiB schema limit.
- Apply response schema and field-projection changes together. Canceling a schema or operation modal discards changes within that window; nested Escape, focus restoration, and unsaved-draft protection are preserved.
- Import OpenAPI in a modal with Available, Needs changes, and Already configured counts and filters. Show why an operation cannot be selected and suggest a resolution, while keeping unsupported operations blocked.
- Include the response HTTP status and nested property location in supported OpenAPI import diagnostics. Runtime response-schema mismatches identify the configured schema location and failed keyword without including response values or dynamic object keys.

## Upgrade notes

- **No new database migration is introduced.** Installations upgrading from v0.1.5 already have the required schema. Older installations must apply the existing migrations through **31** before deploying current services.
- Update the web UI and control/data-plane services to receive both the editing experience and improved diagnostics. Existing REST definitions, credentials, header mappings, and runtime response validation retain their behavior.
- In the schema workspace, **Apply schema** updates the operation window. **Apply operation** updates the upstream draft. **Save** persists the upstream and publishes its tool definitions.
- Paste a raw REST body as the example, rather than the MCP result envelope. Inferred fields remain optional until marked required. Choose number instead of integer when fractional values are valid, and allow null where the service can return it.
- Browser schema checks are an early aid; backend validation remains authoritative. One example cannot describe every possible response. Merge preserves existing constraints, so a conflicting example requires an explicit schema adjustment or replacement.
- REST execution tests still send real requests using saved configuration. A response-schema mismatch can occur after the upstream has completed an operation; requests are not automatically replayed.

See the [REST operation and schema workspaces guide](https://github.com/bishoku/vmcp/blob/v0.1.6/docs/Upstreams.md#rest-operation-and-schema-workspaces) for the complete editing and import flow.

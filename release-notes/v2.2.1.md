# vMCP v2.2.1 — understandable access management

Application version: v2.2.1. OpenAPI version: 2.2.1. Helm chart version: 2.2.1.

## Access Management

- Claim mappings now have names and descriptions. Existing unnamed mappings show
  readable claim conditions; assignment references continue using stable IDs.
- Assignments are the primary view, showing who receives which role on which
  resource, with configuration warnings and secondary copyable identifiers.
- Grant access guides administrators through identity, role, scope and review.
  A claim mapping can be created within the flow and is saved separately. New
  mappings and assignments still start disabled.
- Role and mapping cards expose related assignments and contextual actions.
  Review summaries explain disabled dependencies, scope incompatibilities and
  shared change impact. Payload controls appear only for relevant roles.
- Test access prefills simulation from a saved assignment and shows named results.
  Simulations evaluate stored policy, not authentication or claim freshness, and
  include all saved assignments. Unmanaged audit grants use an audit-event target.
- Existing shared UI standards are retained, with desktop/mobile and keyboard
  coverage. Platform administrator authority and permission semantics are unchanged.

## Upgrade and compatibility

Migration 47 adds bounded name and description columns to claim mappings. It does
not rewrite matching conditions, identity references or existing grants. Back up
PostgreSQL before upgrading and let the chart's migration job finish before new
application components start. Use chart 2.2.1 with this release's matching signed,
digest-pinned image overlay.

The mapping API accepts omitted display metadata for legacy clients. The console
requires a name when saving a mapping; existing records remain usable and readable
before naming. Renaming does not change which identities match. No new environment
variables or credentials are required.

For installations upgrading from older releases, follow intervening notes,
including the legacy approval-hook removal documented in v2.0.1. This release does
not restore that hook.

## Rollback

Restore the previous matching chart and image overlay. The additional columns can
remain in place with v2.2.0. An explicit rollback of migration 47 removes mapping
names/descriptions but preserves conditions and assignments; back up metadata
before doing so. Do not run v2.2.1 management endpoints against the rolled-back schema.

# vMCP v2.1.3 — configurable invocation-service authentication

Tracking issue: #71. Includes invocation-service integrations (#69 / PR #70),
access-management improvements (#67 / PR #68), and independent Omni egress
(#65 / PR #66, previously released in chart 2.1.3).
Application version: v2.1.3. OpenAPI version: 2.1.3. Helm chart version: 2.1.4.

## Invocation-service integrations

- Shared and upstream-local verification and approval services support static
  Bearer authentication, OAuth2 client credentials, custom authentication headers,
  and explicitly unauthenticated services. Existing configurations retain Bearer
  behavior. OAuth2 supports client authentication through Basic or form parameters,
  scopes and an optional audience, with cached access tokens.
- Configure each service's timeout from 1 to 60 seconds; the default remains two
  seconds. Token acquisition shares the invocation phase deadline. Token and
  service requests retain the gateway's egress controls and private CA support.
- Credentials remain write-only in management responses. The UI supports the new
  modes for both shared and local services without changing policy inheritance.
- Download `api/invocation-service.openapi.yaml` for the external service v1
  contract. `docs/Invocation-Security.md` and
  `docs/Invocation-Service-Adapters.md` include request/response examples,
  authentication setup, enterprise adapter guidance, and failure recovery.
- The check/consume protocol, fail-closed decisions, single-use execution
  reservation, and existing audit persistence guarantees remain unchanged.
  The external service contract version remains 1.0.0.

## Access management, deployment and security

- Access-management screens explain permissions and align their editors for
  clearer configuration and review.
- The chart includes independent `omni.egressAllowCIDRs` and
  `omni.egressAllowHosts`; Omni does not inherit control/data-plane egress grants.
  Configure these explicitly when using private model destinations.
- Go and the pinned build image are updated to 1.27.4 to address GO-2026-6859.

## Upgrade and rollback

Upgrade matching application components using this release's digest-pinned image
overlay and chart 2.1.4. Chart 2.1.3 was already published with application v2.1.2;
the chart and application version numbers therefore differ intentionally.
No new database migration is introduced by this patch. Earlier upgrades must
still follow intervening release notes, including migration 46 from v2.1.1.

Before rolling back to v2.1.2, restore service configurations compatible with that
version: static Bearer credentials and the default timeout. Older binaries do not
support the new authentication modes or configurable timeout. No database
down-migration is needed for this patch. Keep chart 2.1.3 or newer if independent
Omni egress grants are required.

The legacy global `VMCP_APPROVAL_URL` approval hook remains removed, as documented
in v2.0.1. Deployments retaining it fail startup; this patch does not restore it.

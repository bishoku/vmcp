# vMCP v2.3.0

## MCP interoperability

- Virtual and Omni can serve legacy (2025-06-18) and modern (2026-07-28) tools clients while the gateway independently selects the upstream revision. Dual-revision native Streamable HTTP upstreams use modern requests when enabled. Set `VMCP_MCP_20260728=1` on the control plane, all data-plane replicas and Omni MCP to opt in. Legacy remains the default.
- The control-plane and data-plane compatibility suite exercises nine upstream profiles with Go, TypeScript and Python FastMCP, including 36 downstream combinations, replica-local preference expiry, failover and lost replies. The FastMCP modern-only fixture enforces the revision with an ASGI deployment policy.
- Omni and modern Virtual open a fresh session for each invocation on a legacy upstream. Multi-step tools need resources that survive the upstream session and can be addressed on later calls. See the [protocol contract and browser example](https://github.com/bishoku/vmcp/wiki/MCP_PROTOCOL_CONTRACT#tool-calls-across-revisions).

## Management and deployment

- Configure the maximum lifetime of verified browser SSO claims with `VMCP_OIDC_CLAIM_TTL_SECONDS` or Helm value `runtime.oidc.claimTTLSeconds`. The default is 900 seconds and the verified ID token expiry still caps the lifetime. The setting takes effect at the next sign-in.
- The web image uses the patched nginx 1.30.7 runtime.

## Upgrade and rollback

Use Helm chart 2.3.0 with the matching release image overlay, or the versioned Kustomize bundle. The database schema remains at migration 47. Roll out matching component versions before enabling modern requests and keep the flag consistent across replicas. Before rolling back to v2.2.3, switch clients and upstreams to a supported legacy path.

# Upstream-owned invocation security

vMCP v2.1.0 moves invocation policy management into the upstream workspace.
The Helm chart and OpenAPI document are both version 2.1.0.

## Changes

- Upstream owners with explicit permissions can manage their upstream's default
  invocation policy, tool rules, and local verification and approval services.
  Local services are scoped to that upstream. Platform operators manage shared
  services in Settings. [PR #50](https://github.com/bishoku/vmcp/pull/50)
- MCP and REST tool rows show the effective policy, including inherited
  requirements. Review affected tools before saving, tighten a tool's policy, or
  remove its own rule to return to the upstream default. Scoped saves detect
  conflicting edits to the same upstream.
- Settings groups gateway information, security and audit, API access, and
  configuration. The policy and audit editors use the console's shared controls.
  [PR #45](https://github.com/bishoku/vmcp/pull/45)

## Upgrade from v2.0.1

1. Back up PostgreSQL, deployment values, Secrets, and the encryption keys. Apply
   migration **45** with the matching migration image or the Helm migration job,
   then deploy matching v2.1.0 components. Upgrade all configuration writers
   before enabling upstream-local services.
2. Existing policies and encrypted credentials are preserved. Existing service
   definitions become shared services and retain their references. The tenant API
   and GitOps export/apply continue to support whole-document configuration.
3. Assign `upstreams.invocation_security.read` and
   `upstreams.invocation_security.manage` to the appropriate roles at team or
   upstream scope. Migration 45 adds the permissions to the built-in Platform
   Operator role. Custom roles require explicit grants.
4. Confirm that teams can manage their own upstreams, inspect inherited rules,
   and run representative protected calls before reopening traffic. Use a tested
   database restore with matching binaries and keys if rollback is required
   after configuring upstream-local services.

For upgrades from v2.0.0 or earlier, the legacy `VMCP_APPROVAL_URL` hook was
removed in v2.0.1. A data plane configured with it refuses to start. Follow the
[v2.0.1 upgrade checklist](https://github.com/bishoku/vmcp/blob/v2.0.1/release-notes/v2.0.1.md#upgrade-from-v200)
to configure replacement policies before reopening protected traffic.

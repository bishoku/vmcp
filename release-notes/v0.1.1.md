# A visual REST-to-MCP workspace

vMCP v0.1.1 makes REST upstream configuration easier with a single workspace for OpenAPI import, operation editing, and live MCP tool previews. It also improves upstream failure diagnostics and long-lived stream reliability.

## Highlights

- Import OpenAPI/Swagger operations inline, inspect candidate tools, and edit operations without leaving the workspace. Path placeholders automatically create parameters; query parameters have visual type, description, and required controls.
- Generate request and response schemas from example JSON. Edit nested objects and list items visually, including descriptions and required fields. Example values are not saved with the upstream.
- Generate a response schema from a successful saved-operation test. Execution still requires administrator access and confirmation; tests use saved configuration and credentials, while generated schemas remain in the draft until Save.
- Preserve imported constraints, required fields, and complex schema definitions. Ambiguous examples require an explicit type choice; advanced JSON editing remains available for unsupported constructs.
- Select the top-level response fields returned to agents with checkboxes. MCP previews update immediately, and saved selections filter both structured and text tool output. Objects and lists retain their entire contents. Invalid selections block saving instead of silently exposing the full response.
- Keep invalid JSON local, block saving until it is corrected, and require explicit discard when navigating away from unfinished edits. The workspace supports desktop and mobile layouts.

## Reliability and diagnostics

- Add safe upstream error reasons and details, execution stage, virtual server, request/trace identifiers, and call duration to transport-failure logs. Raw URLs, credentials, headers, and response bodies are not included in diagnostic details.
- Preserve typed REST transport errors so egress policy blocks, DNS, TLS, timeout, and connection failures can be distinguished in logs.
- Clear per-write SSE deadlines after flushing, preventing idle streams from being closed by a stale write deadline.
- Allow `httpbin.org` in the demo environment's explicit egress host list for REST examples. Production egress policy remains operator-controlled.

## Upgrade notes

No new database migration is introduced by v0.1.1. Installations upgrading from versions older than v0.1.0 must also follow the [v0.1.0 migration instructions](https://github.com/bishoku/vmcp/releases/tag/v0.1.0).

Update the web, control-plane, and data-plane images to receive the complete release. Existing REST configuration and response-field selection remain compatible. Full response mode includes undeclared properties; selected-fields mode omits them. Nested field selection is not included in this release.

## Validation

Local validation passed 196 frontend tests, desktop/mobile REST workspace and import browser scenarios, targeted Go diagnostics/REST/stream tests, frontend production builds, and lint checks. A live authenticated gateway call to httpbin verified that the advertised output schema and both MCP content forms expose only selected fields. Full release CI and multi-platform image publication are enforced by the release pipeline before publication.

# vMCP v2.4.0

## Breaking change to REST tool arguments

REST operations with an object request body expose its top-level fields directly.
For an operation with path argument `id` and body field `text`, update calls from
`{"id":"7","body":{"text":"Ready"}}` to `{"id":"7","text":"Ready"}`. The HTTP body
remains `{"text":"Ready"}`. Nested fields keep their structure. A root array uses
one required argument named `body` by default. Set **Array argument name** in
the operation editor to choose another name. [PR #135](https://github.com/bishoku/vmcp/pull/135)

## REST operation editor

- Open **Details** to inspect agent inputs, fixed parameters, the HTTP request and the projected result. Parameter rows show whether the agent supplies a value or the gateway uses a fixed value or fallback.
- **Preview** and **Test** use the saved operation. Apply edits to the upstream draft, then save the upstream to test those changes.
- Choose **Plain text** under **Request & response schemas** to convert a JSON response. The editor asks for confirmation before removing its response schema and selected fields from the draft. [PR #133](https://github.com/bishoku/vmcp/pull/133)

## Upgrade from v2.3.3

Helm chart 2.4.0 targets application v2.4.0. This release requires no database migration.

1. Before upgrading, review saved operations for collisions between path, query
   (including fixed parameters) and top-level body names. Resolve collisions and
   schemas with ambiguous root types. Review whole-object constraints on bodies
   combined with URL parameters as described in [Upstreams](https://github.com/bishoku/vmcp/blob/v2.4.0/docs/Upstreams.md#diagnose-rest-request-body-mapping).
2. Pause tool traffic and upgrade the web UI, control plane and all data-plane replicas.
3. Open each existing REST upstream and choose **Refresh Tools**, or POST to
   `/api/v1/upstreams/{slug}/refresh-tools`. This regenerates saved tool schemas
   locally and preserves virtual server selections and aliases.
4. Reload the client's tool list, update saved calls, and verify an example with
   **Preview request** before resuming traffic.

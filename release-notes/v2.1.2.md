# vMCP v2.1.2 — consistent upstream editing and shared web formatting

Tracking issue: #61. Includes upstream detail improvements (#57 / PR #58) and
shared web formatting enforcement (#59 / PR #60), and a partial-save retry race fix (#64).
Helm chart and OpenAPI version: 2.1.2. Application version: v2.1.2.

## Upstream detail improvements

- Connection configuration, invocation defaults, local verification/approval
  services, tool policies and audit masking share **Edit upstream** and one sticky
  **Save / Cancel** bar. Security and masking controls no longer mutate configuration
  from the read-only view.
- REST operation and discovered MCP tool rows show their policy source and link
  to the matching tool in one central policy editor. Effective requirements are
  shown as labeled rows; tool-specific settings and inherited defaults remain
  distinct. Search, expandable tool rows and mobile layouts reduce duplication.
- Invocation security and audit masking use the same page width, spacing and
  disclosure groups as the other configuration sections. Saved local masking
  rules and service usage can be reviewed without entering edit mode.
- Save writes only changed sections through their existing, independently
  revisioned endpoints. These writes are **not atomic**: if a request fails,
  completed sections remain applied, pending drafts are retained, and retry skips
  completed writes. Cancel discards unsaved changes, not previously saved changes.
- Save/retry decisions inspect the current draft synchronously. A successful
  section is not submitted again while React dirty-state effects are still
  settling; genuinely new edits remain eligible for saving. Cancel likewise
  restores the latest successful baseline even before a new render.
- Existing scoped permissions, write-only credentials, conflict checks and policy
  inheritance remain in force. Audit-only editors can edit local masking without
  acquiring connection-update access. Global and virtual-server audit workflows
  retain their existing behavior.

## Shared web formatting and developer setup

- Prettier 3.9.10 is pinned in the web package and lockfile. Existing web source and
  test files are consistently formatted; no application logic change is intended.
- `npm run dev`, `npm run build` and `npm run preview` format before starting.
  `format:check` checks without modifying files; the required web CI job runs it
  before any build can rewrite violations.
- Dependency setup installs the tracked `.githooks/pre-commit` hook. It checks
  staged web blobs, including partially staged files, and rejects unformatted or
  invalid source without rewriting or staging files. Missing web dependencies
  block web commits; non-web commits do not require web packages.
- Repository-tracked editor settings, EditorConfig, LF Git attributes and mandatory
  contributor/AI-agent instructions keep the same rules across checkouts.
  Local hooks can be bypassed outside the supported workflow; protected-branch
  CI remains the final enforcement boundary.
- Existing developer checkouts must run **`npm ci --prefix web` once** after
  updating. This installs the locked formatter and sets `core.hooksPath` to
  `.githooks`. Review and stage intended changes after formatting. See
  `CONTRIBUTING.md` for the commands and editor setup.

## Upgrade and rollback

Upgrade matching components and the chart from v2.1.1 to v2.1.2 using the release's
immutable image overlay and packaged chart. No additional database migration,
API contract change or permission grant is required by this patch. Upgrades from
older versions must still follow the migration and behavior guidance in their
intervening release notes, including migration 46 introduced in v2.1.1.

Rollback to v2.1.1 requires no database down-migration for this patch. The former
UI/editing workflow returns, while already saved configuration remains in effect.

The v2.0.1 invocation-security history is unchanged: the legacy global
`VMCP_APPROVAL_URL` approval hook was removed, and deployments retaining it fail
startup. This patch does not restore the hook; see `v2.0.1.md`.

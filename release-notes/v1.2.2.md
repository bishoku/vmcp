# Omni discovery quality and diagnostics

vMCP v1.2.2 improves Omni discovery and embedding troubleshooting while keeping
reranking and anonymous discovery disabled by default. There are no database
migrations or API path changes in this patch. Chart and OpenAPI versions are 1.2.2.

- Structured embedding and reranker diagnostics expose safe failure reasons,
  HTTP status, timing, repeated-failure summaries and recovery in pod logs.
- Optional anonymous Omni access discovers and invokes only published anonymous
  virtual servers. Enable `VMCP_OMNI_ALLOW_ANONYMOUS=true` on both data plane and
  Omni; tool approvals and current access checks still apply.
- Embedding profiles support dimension validation, model revision, query/document
  prefixes and an optional tool-first text format. Invalid or incomplete vectors
  fall back consistently; keyless on-prem providers remain supported.
- An optional HTTP reranker reorders authorized candidates with fresh access
  checks before model dispatch and final result filtering. Configure candidate
  count, timeout, per-tool score floor, query-level no-match threshold, uncertain
  ordering guard, failure policy and isolated TLS verification settings.
- Console discovery shows reranker configuration and explains no-match results.
  Installation guides document embedding/reranker API contracts and environment
  variables for Helm and non-Helm deployments.

Reranking requires a separately operated compatible model endpoint; no model
weights or Python runtime are bundled in the Omni image. All score thresholds
remain zero by default and require calibration for the selected model. Use
`VMCP_OMNI_RERANK_FAILURE_POLICY=closed` if provider failures must not return
unfiltered retrieval results under a no-match policy.

Local development evaluation used 1,000 synthetic tools and 90 intents with real
embedding/reranking models. The selected opt-in policy improved positive Hit@1
from 62/80 to 65/80, preserved Hit@5 at 75/80, and reduced out-of-catalog false
suggestions from 10/10 to 0/10. Two valid Turkish intents returned no match because
their expected tools were absent from retrieval candidates. Sequential CPU search
p95 was approximately 1.64 seconds. This is a known development corpus, not an
independent production quality or throughput guarantee. Further performance and
independent quality acceptance are deferred from this release.

Validation includes Go race/vet checks, Helm rendering, browser scenarios, model
contract and failure-policy tests, access revocation tests and real-model quality
measurements. Publication additionally runs the repository's standard CI,
architecture-specific vulnerability scans and image signature verification.

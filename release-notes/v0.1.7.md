# Nested REST response field selection

vMCP v0.1.7 lets REST tools return selected nested properties, including fields inside arrays, while keeping their advertised MCP output schema aligned with the actual response.

## Highlights

- Expand response branches in the schema workspace's **Fields returned to the agent** section and search by property name or nested path. Select a complete branch or individual children such as `order.items[].productId` and `order.items[].quantity`.
- Apply array selections to every item, including root arrays and nested arrays. Preserve array order, item count, null values, empty arrays, and absent optional properties.
- Apply the same projection to structured and text tool output and to the MCP output schema. Validate the original upstream response before projecting it; trim required-property lists and remove constraints that pruning could invalidate.
- Preserve existing literal top-level `responseFields` settings. Store nested selections as `responseFieldPaths`, using arrays of literal property names so dots, slashes, and asterisks in names are unambiguous.
- Reject unknown, duplicate, or overlapping paths. Keep at least one UI selection unless Full response is explicitly chosen, and show schema-drift and selection-limit errors before saving.
- Verify API save/update/export/import, runtime snapshot propagation, real virtual MCP calls, concurrent projection, matching browser/backend schemas, and mobile/desktop modal persistence.

## Upgrade notes

- **No new database migration is introduced.** Installations upgrading from v0.1.6 already have the required schema. Older installations must apply existing migrations through **31**.
- **Update every control-plane and data-plane instance before saving nested selections.** Older binaries do not recognize `responseFieldPaths` and may return the full response. Update the web UI as part of the rollout and refresh clients' `tools/list` after changing selections.
- Selecting a parent returns its entire contents. Unchecking a child narrows that branch to its remaining declared fields; narrowed branches omit unselected and undeclared properties. Full response keeps the original response.
- Nested paths support up to 256 selections, 32 property names per path, and 1024 UTF-8 bytes per property name. Do not configure nonempty `responseFields` and `responseFieldPaths` together. Empty or omitted selections return the full response.
- Child selection requires declared object properties or homogeneous array item schemas. Complex branches using composition such as `oneOf` can be selected whole; selecting their children is not supported.
- Response validation still happens after the upstream request completes. A validation failure does not imply that a write operation was rolled back; requests are not automatically replayed.

See the [response field selection guide](https://github.com/bishoku/vmcp/blob/v0.1.7/docs/Upstreams.md#select-the-fields-returned-to-agents) for configuration examples and behavior.

# vMCP v2.2.0 — direct Omni tool discovery

Application version: v2.2.0. OpenAPI version: 2.2.0. Helm chart version: 2.2.0.
This minor release simplifies Omni discovery and realigns application and chart
version numbers after application v2.1.3 / chart 2.1.4 (#73).

## Omni API removal and client migration

This release intentionally includes a breaking change to the Omni tool surface:

- `discover_server` is removed completely.
- `server_id` is removed from public tool inputs. Discovery accepts `query`,
  optional `project`, and optional `limit`; no server-selection step is required.
- The supported workflow is `discover_tools` → `get_tool_schema` → `invoke_tool`.
  Describe the needed capability in the context of the user's goal and preserve
  explicit project restrictions.
- Removed tool calls and removed input fields return invalid-parameters errors.
  Update clients, stored workflows and cached tool definitions before using this
  release. Reconnect clients to refresh initialize instructions and tool metadata.

Initialize instructions, tool descriptions, the embedded workflow resource,
documentation, UI and SDK interoperability coverage now use the three-tool flow.
The resource remains at `omni://guides/discovery-workflow/v1`; its content is
updated with the binary, so refresh any client-side cached copy.

Tool references remain opaque and retain the virtual-server/exposed-tool route.
Schema retrieval and invocation use the returned reference unchanged. Runtime
authorization, schema-version enforcement, upstream approvals, policy, PII,
quotas, and audit context remain in effect. Similar-looking references are not
interchangeable; do not automatically retry failed or uncertain invocations.
Server metadata remains in discovery results for context; it is not an input
requirement. The old server-grouping search path is removed.

## Version alignment and upgrade

The application advances from v2.1.3 to v2.2.0 and the chart from 2.1.4 to 2.2.0.
No existing tag or chart package is replaced. Use the 2.2.0 chart and this release's
signed, digest-pinned `helm-images.yaml` together, and upgrade matching application
components, including Omni.

There are no new database migrations or environment variables in this release.
For older installations, follow intervening upgrade notes, including migration
46 from v2.1.1 and the legacy approval-hook removal documented in v2.0.1.

## Rollback

Restore the prior matching chart and image overlay, and restore client workflows
appropriate to that release. No down-migration is required for v2.2.0 itself.

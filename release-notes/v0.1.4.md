# Per-call caller context propagation

vMCP v0.1.4 adds opt-in forwarding of agent-supplied user tokens and chat context from tool-call metadata to MCP and REST upstreams.

## Highlights

- Configure a metadata namespace and an explicit list of string fields per upstream through the Caller context editor, API, or declarative configuration.
- Forward selected fields in MCP tool-call metadata over Streamable HTTP and legacy SSE while preserving gateway-managed progress correlation.
- Map selected fields to REST request headers, optionally prefixing an Authorization value with Bearer. Reject conflicts with static headers, managed authentication, and reserved transport headers.
- Keep values scoped to each call, including concurrent calls within the same MCP session. Missing required fields and invalid values are rejected before dispatch; missing optional fields are omitted.
- Keep token verification and application authorization at the upstream. Gateway authentication remains separate; vMCP does not exchange, refresh, or validate caller-context tokens.
- Preserve configuration through save, reload, import/export, and runtime snapshot updates. REST previews show mapping placeholders; required context is tested through actual MCP calls.

## Upgrade notes

1. Back up the database and apply migration **30 (`00030_caller_context.sql`)** before deploying the updated services.
2. Update all control-plane and data-plane nodes and the web UI before enabling caller context. Older nodes do not implement the new forwarding rules. Existing upstreams remain disabled for this feature by default.
3. Configure only trusted upstream destinations, including MCP fallback URLs. Supply fresh context on each tool call; chat session identifiers are independent of MCP session identifiers.
4. Audit and log masking behavior is unchanged. This release does **not** guarantee exclusion of caller-context tokens from existing recording paths. Evaluate those policies separately before forwarding production tokens.

Up to 16 fields can be selected. Values must be strings without CR, LF, or NUL, at most 8 KiB per field (including a configured Bearer prefix); incoming metadata is limited to 32 KiB when forwarding is enabled. See [Upstreams](https://github.com/bishoku/vmcp/blob/v0.1.4/docs/Upstreams.md#per-call-caller-context) for configuration and call examples.

Rolling back migration 30 removes the saved caller-context rules. Disable this feature before rolling back service versions; older binaries do not enforce its required-field settings.

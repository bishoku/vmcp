# Omni MCP call auditing and discovery diagnostics

vMCP v1.2.5 adds audit visibility for `discover_server`, `discover_tools`,
`get_tool_schema` and `invoke_tool`. Chart and OpenAPI versions are 1.2.5.

- Filter **Activity → Omni MCP** to inspect call identity, timing, outcome and
  explicitly linked virtual-server/upstream operations.
- Independently enable client request/response capture, discovery diagnostics,
  embedding model payloads and reranker payloads in **Settings → Audit capture &
  masking**. Payload capture defaults off; operation metadata is recorded.
- Discovery diagnostics include authorization/scope exclusions, embedding state,
  retrieval candidates and scores, reranker scores and thresholds, fallback and
  no-match decisions, and final authorization filtering. Candidate identities and
  unauthorized samples are separately configurable and bounded.
- Payloads retain existing encryption, masking, retention, administrator-only
  access and exporter opt-in. Omni conservatively applies global rules plus the
  union of local masking rules. Model headers/endpoints are not captured.

## Actions for existing installations

1. Upgrade the application components together using this release's chart and
   `helm-images.yaml` digest overlay. In particular, **upgrade data-plane before
   starting the new Omni version**, or use a maintenance window: v1.2.5 Omni
   requires the new private data-plane audit endpoints. An old data-plane cannot
   serve new Omni tool calls. Upgrade control-plane and web as well to configure
   capture and inspect the new activity. Keep existing database, Redis, Secrets,
   master key, ownership configuration and model configuration.
2. No new database migration, environment variable or model deployment is required
   for this patch. Preserve the existing private internal route boundary and
   shared Omni/data-plane authentication settings; do not expose `/internal/*`.
3. After upgrade, open **Settings → Audit capture & masking** and explicitly
   enable the desired Omni capture scopes. Enable candidate identities/scores for
   detailed ranking analysis; unauthorized identity samples require a separate
   opt-in. Defaults are 100 sampled candidates per stage, maximum 200. Enabling
   capture is prospective and cannot reconstruct old payloads. Review masking
   rules and storage/retention capacity before enabling vector/provider payloads.
4. Verify a discovery call under **Activity → Omni MCP**, then load its discovery
   pipeline payload as an administrator. Invoke a discovered tool and check the
   linked Omni → virtual-server → upstream flow. Background index refreshes remain
   operational logs/metrics and are not agent discovery audit events.
5. Strict audit mode now also applies to Omni calls: admission must persist before
   dispatch and completion before success is returned. If completion fails, a 503
   may follow an already executed invocation; **do not automatically retry** it.
   Preserve the configured audit mode and monitor audit storage/queue health.

For an existing quickstart release, download and verify all four assets first:

```sh
release_dir=$(mktemp -d)
gh release download v1.2.5 --repo bishoku/vmcp --dir "$release_dir" \
  --pattern SHA256SUMS --pattern helm-images.yaml --pattern images.json \
  --pattern vmcp-1.2.5.tgz
(cd "$release_dir" && sha256sum -c SHA256SUMS) && \
helm upgrade vmcp-demo "$release_dir/vmcp-1.2.5.tgz" \
  --kube-context microk8s --namespace vmcp-demo --reuse-values \
  -f "$release_dir/helm-images.yaml" \
  --atomic --wait --wait-for-jobs --timeout 20m
```

Use your own context, namespace and release name where different. Back up first.
This command preserves stored values and data; it does not rerun quickstart/demo
seeding. Helm may roll Omni and data-plane concurrently, so pause Omni traffic
until both updated workloads are ready, or stage their rollout in your deployment
process to avoid temporary mixed-version failures.

See the [Omni audit guide](https://github.com/bishoku/vmcp/blob/v1.2.5/docs/Omni-MCP.md#omni-call-audit-and-discovery-diagnostics-v125).

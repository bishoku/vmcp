# vMCP v2.4.2

## OpenTelemetry for gateway services

Control-plane, data-plane and omni-mcp can now send metrics, logs and traces directly to an OpenTelemetry Collector over OTLP/HTTP. Set `OTEL_EXPORTER_OTLP_ENDPOINT` on each service to the Collector's base URL. Each service continues to expose its existing Prometheus metrics at `/metrics` and write structured logs to stdout. If both ingestion paths feed the same backend, enable one path per signal to avoid duplicates. [Operator guide](https://github.com/bishoku/vmcp/blob/v2.4.2/docs/OBSERVABILITY.md#opentelemetry)

Omni gateway requests propagate trace context to the data plane, and request-scoped logs include trace and span IDs. The control and data planes now refresh audit backlog measurements in the background every 30 seconds. Scrapes and OTLP exports read the cached measurements. After a failed refresh, the gauges are absent until the next successful sample. [PR #143](https://github.com/bishoku/vmcp/pull/143)

## Upgrade from v2.4.1

Helm chart 2.4.2 targets application v2.4.2. The database schema remains at migration 48. Existing trace-only configurations continue to work, and deployments using only stdout and Prometheus can upgrade with their current settings.

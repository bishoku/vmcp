# vMCP v2.2.2

## REST upstreams

- Import OpenAPI or Swagger JSON and YAML documents up to 5 MiB. For partially converted operations, the import dialog shows the conversion error and offers a repair editor when a partial definition is available. Repair drafts start disabled. Review them during the current import session, apply the selected operations, then save the upstream.
- Review operations in a full-width list. Open a tool preview from its row or inspect the current tool definition while editing an operation.
- Move REST operations between environments with **Export operations** and **Import operations file**. Review additions and updates by tool name before applying them to the destination draft. Descriptions, parameters, schemas and response mappings travel with the operations. The destination keeps its URL, credentials, operation headers and destination-only tools. Renaming a tool creates a separate entry on import.
- Inspect literal parameter defaults, descriptions and schema values before sharing exported files.

## Management console

- Discover capabilities from a saved MCP upstream and reload the resulting catalog on its detail page.
- Team and project editors preserve keyboard focus when editing ownership settings.

## Upgrade and rollback

Use Helm chart 2.2.2 with the release image overlay. The database schema remains at migration 47. For deployments behind an additional reverse proxy, allow up to 32 MiB for the JSON-wrapped import request and 16 MiB for upstream writes. The application checks the decoded source against its 5 MiB limit. Import previews retain the 1,000-source-operation and 8 MiB expanded-result limits.

REST configurations can now reach 12 MiB. Mock configurations retain their 512 KiB limit. Before rolling back to v2.2.1, reduce any REST configurations exceeding the previous 512 KiB limit while v2.2.2 is still running, then restore the matching v2.2.1 chart and image overlay.

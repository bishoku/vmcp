# Embedding TLS compatibility

vMCP v1.2.1 adds an explicit opt-in for self-signed embedding HTTPS endpoints:

```env
VMCP_OMNI_EMBEDDING_INSECURE_SKIP_VERIFY=true
```

The default remains `false`. When enabled, only the Omni embedding client skips
certificate-chain and hostname verification; HTTPS encryption remains active.
Data-plane connections and upstream TLS settings are unaffected. Invalid boolean
values stop Omni startup. Restart/recreate Omni after changing its environment.

Docker Compose passes the variable through. Helm exposes
`omni.embeddingInsecureSkipVerify: true`. Use the v1.2.1 image; v1.2.0 does not
recognize this option. There are no new database migrations or API path changes.
The chart and OpenAPI versions are 1.2.1.

Validation covers rejection of an untrusted TLS certificate by default, successful
embedding with explicit opt-in, and isolation from other HTTP clients.

See [installation and environment variables](https://github.com/bishoku/vmcp/blob/v1.2.1/docs/Omni-MCP-Installation.md)
and [changes since v1.2.0](https://github.com/bishoku/vmcp/compare/v1.2.0...v1.2.1).
